# HairMatch 操作テスト報告

実施日：2026年9月5日。対象：http://127.0.0.1:4173 のローカル実装。

## 結論

診断の完了・結果表示・詳細・保存・比較・履歴まで操作は完走できる。通常操作中のJavaScript例外は検出されなかった。一方、終了・再開・修正後の戻り先などの導線には改善余地があり、保存失敗時の成功通知は不具合として修正が必要。

今回は検証と報告を実施。アプリ本体の変更・commit・pushは行っていない。

## 検証方法と範囲

- ローカルChromeを隔離したテスト用プロファイルで起動。普段のユーザーデータは変更していない。
- 操作テストでは対象要素までスクロールし、固定ナビに隠れていないことを確認したうえで、画面座標へのポインター入力を実行。
- 診断全8ステップ、未回答制御、選択、前へ、ブラウザの戻る、リロード、回答修正、結果・詳細の往復、保存・比較、検索、履歴の開閉を検証。
- 390×844のスマートフォン相当表示を中心に操作・画像確認。マイページの横方向のはみ出しは320・390・768・1440pxで検査。既存テストでは各主要画面の390px表示とPC表示も確認。
- 保存容量不足はテスト用ブラウザ内でlocalStorageの書き込み失敗を再現。
- 日本語入力については変換中のイベントを模擬してDOMの保持を検査。Windows IMEやiPhone・Android実機での変換操作自体は未検証。
- `npm.cmd test`：12件成功。
- `node tests/browser.mjs`：基本機能・履歴の回帰テスト成功。
- `node tests/usability.mjs`：操作監査。観測結果を `test-results/usability-observations.json` に出力。

## 再現した問題と修繕案

### 1. 保存失敗時に成功通知が出る【優先度：高／再現済み】

手順：保存容量不足を模擬 → 商品のお気に入りボタンを押す。

結果：書き込みは失敗しているのに「お気に入りに保存しました」と表示された。`save()` が出した失敗通知を、その後の成功通知が上書きしている。画面内の一時状態は変わるため、ユーザーは保存できたと思ってしまう。

修繕案：保存関数が成功／失敗を返し、成功時のみ成功通知を出す。失敗時は「この画面では保持していますが、端末への保存はできませんでした」と区別する。同じ保存関数を使う比較・診断履歴についても成功表示の条件を確認する。

### 2. 日本語の変換中に検索入力欄が作り直される【優先度：高／模擬イベントで確認】

手順：検索欄に変換開始と `isComposing: true` の入力イベントを発生させる。

結果：入力前後で検索欄のDOM要素が別のものになった。変換中でも画面全体を再描画するため、日本語変換が途切れる可能性がある。実際のIMEでの途切れは未検証。

修繕案：検索欄を保持し、結果一覧だけ更新する。`compositionstart`〜`compositionend` の間は検索確定処理を待つ。改修後はWindows IMEとスマートフォン実機で確認する。

### 3. 診断・結果に明示的な終了ボタンがない【優先度：中／再現済み】

診断のヘッダーは前へと進捗のみ。結果ヘッダーにも閉じる・戻るはない。下部タブで離れることはできるため、操作不能ではない。

改善案：診断に「保存して閉じる」、結果に「閉じる」を追加。診断の終了先はホーム、履歴の終了先はマイページなど、遷移元に合った戻り先を設ける。途中の回答を捨てる操作とは区別する。

### 4. 再読み込みで診断の進捗が1問目に戻る【優先度：中／再現済み】

手順：3 / 8まで進む → 再読み込み。

結果：1 / 8になる。回答は保存されているが、ステップ位置は保存されていない。さらに、2 / 8でブラウザの戻るを実行すると1 / 8ではなくホームに戻った。

修繕案：回答とともに現在のステップを保存し、ホームに「続きから再開」を出す。各ステップの履歴をURL／History APIに対応させ、ブラウザの戻ると画面内の戻るの動きを合わせる。

### 5. 確認画面からの修正後に、残りの質問を再び通る【優先度：中／再現済み】

手順：8 / 8 → 髪質の「変更」 → 太さを変更 → 次へ。

結果：8 / 8の確認には戻らず3 / 8へ進む。その後も残りの質問を通る必要がある。

修繕案：確認画面から入った修正モードを保持し、「変更を保存して確認へ」を出す。未回答項目が生じた場合のみ、その項目への回答を求める。

### 6. 商品詳細から戻ると結果カテゴリがリセットされる【優先度：中／再現済み】

手順：結果をサロン系に切替 → 商品詳細 → 上部の戻る。

結果：総合おすすめに戻った。

修繕案：結果の選択タブを保持し、必要に応じてスクロール位置も復元する。新しい診断を実行したときだけ初期タブへ戻す。

### 7. キーボード操作中にフォーカスが外れる【優先度：中／再現済み】

手順：お気に入りを切り替える、または検索フィルターを変更する。

結果：操作要素が再生成され、フォーカスがBODYに移った。

修繕案：対象ボタン・一覧だけを更新するか、更新後に同じ操作要素へフォーカスを戻す。保存解除で商品自体が消える場合は、次の商品か一覧見出しへ移す。

### 8. 検索0件のボタンで状況が変わらない【優先度：中／再現済み】

手順：価格3,000円以下を指定 → 0件 → 空状態の「商品を探す」を押す。

結果：価格条件は3,000円のままで、0件の画面に留まる。

修繕案：「条件をクリアして商品を見る」に置き換える。別途存在するクリア操作へ誘導するだけでもよい。

### 9. 長い質問で「次へ」が初期表示から見えない【優先度：低〜中／再現済み】

390×844の仕上がり画面では、未選択時の次へボタン上端が約1,015pxにあった。スクロールすれば押せることは確認しており、隠れて押せない不具合ではない。

改善案：下部ナビの上に「次へ」領域を固定し、本文末尾に十分な余白を確保する。未回答時は不足項目を短く示す。選択カードの縦の占有面積も調整できる。

## 正常だった操作

- 未回答では次へを押せず、必要な回答後は進行できる。
- 画面内の前へで1ステップ戻り、選択状態も保たれる。
- ダメージ「ほぼなし」と「カラー」は同時選択にならない。
- 診断を完了してTOP5を表示できる。
- お気に入り・比較に追加でき、比較4件目は通知される。
- お気に入り・比較・診断履歴の通常保存と再読み込み後の復元は既存テストで成功。
- COTAの検索では2件表示。
- 過去の診断を開き、回答の展開／折りたたみ、当時の商品詳細、再診断へ進める。
- 既存テストでは2回目の診断後も最初の回答・スコアが保持される。
- 調べた主要画面で横方向のページはみ出しはなく、通常操作の例外も検出されなかった。

## 機能追加の候補

1. 履歴の個別削除と「元に戻す」。不要な試行結果を整理できる。
2. 診断履歴へのメモや名前。季節・カラー後など、違いを振り返りやすくする。
3. 前回との違いの表示。変わった回答・1位商品・相性スコアを比較できる。
4. 実商品の価格・容量・成分・画像の整備。現在は価格未確認のため、価格フィルターが常に0件になるのは仕様上正しいが、実用性はまだ確認できない。

## 推奨する改修順

保存結果の正しい通知 → 日本語入力とフォーカス維持 → 閉じる・再開・ブラウザの戻る → 修正後の確認復帰 → 結果カテゴリ保持・0件時の導線 → 次へ領域の改善 → 履歴の整理・メモ。

実機のソフトウェアキーボード、Safari、スクリーンリーダー、ネットワークの遅延時などは今回の検証範囲外。今回の結果をもって全環境での動作保証とはしない。
