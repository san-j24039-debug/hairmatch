# 診断と商品管理の改善（2026年11月24日）

## 診断の基準

現在の商品読み込み時に `data/assessments.json` を結合し、公式の商品説明で確認できる特徴だけを条件一致率として採点する。実測の効果や使用感の点数ではない。最重要の仕上がりは重み3、その他の対象条件は重み1。希望条件に該当する公式記載があれば一致、未記載は未確認として一致には数えない。未記載が不適合を意味しないことを結果・詳細で明示する。

従来の仮評価・追加商品の中立値60は現在の採点には使用しない。泡立ち・キシみ・すすぎ感などの未確認値も不使用。メーターは未確認を「—」と表示し、比較表は記載あり／未確認に分ける。過去の診断履歴は当時のコピーを保持する。

根拠は40商品のみ登録済み。残りの125商品は根拠未登録であり、診断の情報不足を表示する。全165商品で適性を実証済みという意味ではない。特徴の資料は11月15日の公式ページ照合データを使用し、メロウのシャンプー、イオのリラックスメント、HIMAWARIのリッチ2種は11月24日に公式ページを再確認。根拠の出典と確認日を各特徴に保存し、シャンプーの記載を同シリーズのトリートメントへ転用しない。

## 探す・使う

- 検索の並び順：シリーズ順、価格順、商品名順、診断後の条件一致順。未確認価格は価格順の最後。同値の順序は維持。
- ブランドのカタカナ・ひらがな・全角英字・空白違いと複数語に対応。「ルベル」「ひまわり」「ダイアン ビートゥルー」など。
- 詳細から使用中のシャンプー・トリートメントを個別に登録。マイページで確認・解除できる。保存先はこの端末の `hairmatch:currentProducts`。
- 候補の詳細に「使用中の商品と比較」を追加。現在の2商品と候補を重複なしの最大3件で比較する。

## 情報更新管理

マイページの「商品情報の更新状況」から、最終確認日・要再確認（90日以上）・公式ページへ移動できる。`lifecycle.status` はactive／renewed／discontinued、後継IDはreplacementIdで管理。終売は現行検索・診断から除外するが詳細や履歴を破壊しない。

`node scripts/audit-products.mjs` でリンクエラー・取得失敗・メンテナンス・本文の変化を `test-results/product-update-report.json` に記録する。GitHub Actionsの「Review product information changes」を手動実行してもレポートを取得できる。本文ハッシュの基準は `data/source-baselines.json`。初回の124URLの取得結果から基準を記録したが、価格・容量の再確認を意味せず、商品確認日は変更しない。ページ全体の変化は商品仕様変更以外でも起こるため、結果は確認待ちとして扱う。

確認後に管理者がJSONを作り、次のコマンドで適用する。

```powershell
node scripts/review-product-updates.mjs reviewed-changes.json
```

入力例：

```json
{"reviewedAt":"2026-11-24","changes":[{"id":"plus-mellow-shampoo","status":"active","price":1650,"volume":"450mL"}]}
```

価格は税込。変更しない項目は省略する。終売時はstatusをdiscontinued、後継がある場合はreplacementIdを指定。全変更を検証してから商品ファイルを書き換える。公式ページを開けただけでは価格・終売・確認日を自動変更しない。評価根拠は確認した `data/assessments.json` を別途更新する。更新後はテストして通常のmainへのpushで公開する。
